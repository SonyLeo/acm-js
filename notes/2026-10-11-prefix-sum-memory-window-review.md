## 1. 子数组和等于目标值的数量

### 题目模型

给定可能包含正数、零、负数的数组 `nums` 和目标和 `target`，统计所有元素和恰好等于 `target` 的连续子数组数量。

例如：

```js
countSubarraysWithSum([1, -1, 0], 0) // 3
```

合法子数组为：

```text
[1, -1]      // 下标 [0, 1]
[1, -1, 0]   // 下标 [0, 2]
[0]          // 下标 [2, 2]
```

### 前缀和的切分理解

对当前右端点 `right`：

```text
curr = 从数组开头累加到 right 的总和
old  = 从数组开头累加到目标子数组左边界之前的总和
```

图示：

```text
数组开头                              当前 right
|------------------------------------------|
|--------------- old ----------------------| target |
|---------------------- curr ---------------------|
```

它们的关系是：

```text
curr = old + target
curr - old = target
old = curr - target
```

所以，当前累加和为 `curr` 时，只要历史上存在前缀和 `curr - target`，两者中间就有一个和为 `target` 的连续子数组。

更标准的数组下标写法：

```text
prefix[0] = 0
prefix[i + 1] = nums[0] + ... + nums[i]

nums[left...right] 的和
= prefix[right + 1] - prefix[left]
```

### 为什么 Map 存次数

同一个旧前缀和可以出现多次；每次出现都表示一个不同的起点。

在 `[1, -1, 0]` 中，前缀和为 `0` 的位置有：

```text
开始前
下标 1 之后
下标 2 之后
```

当走到最后一个 `0` 后，当前前缀和也是 `0`。寻找 `target = 0` 时，历史中已有两个 `0`，所以以当前下标结尾的合法子数组有两个：`[1, -1, 0]` 和 `[0]`。

因此 Map 的语义是：

```js
countMap.get(prefixSum)
// 前缀和 prefixSum 在当前位置之前出现的次数
```

### 必须保留的初始化与顺序

```js
let prefixSum = 0;
let result = 0;
const countMap = new Map([[0, 1]]);

for (const num of nums) {
  prefixSum += num;

  result += countMap.get(prefixSum - target) || 0;

  countMap.set(prefixSum, (countMap.get(prefixSum) || 0) + 1);
}
```

`0 -> 1` 表示“开始前的空前缀”。它让从下标 `0` 开始的子数组可以被统一统计。

顺序必须是：

```text
当前元素加入前缀和
-> 查询旧前缀和
-> 记录当前前缀和
```

若先记录当前前缀和，`target = 0` 时会把当前前缀错误地与自己配对，相当于统计不存在的空子数组。

### 为什么不用普通滑动窗口

本题允许负数。窗口总和大于目标时，移除左端的负数会让窗口和变大：

```text
窗口 [-1, 5] 的和为 4
移除 -1 后，窗口和变为 5
```

因此“和太大就缩左”不具有单调性，不能保证正确。前缀和 + Map 不依赖元素正负。

### 复杂度与边界

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(n)`，最坏情况下每个前缀和都不同。
- 必测边界：空数组、单元素等于目标、`target = 0`、重复前缀和、负数和零。

## 2. 合法内存记录的受限总占用窗口

### 题目模型

给定：

```js
memory      // 非负整数数组
valueRange  // [minValue, maxValue]
limit       // 子数组总和上限
```

统计非空连续子数组数量，要求：

```text
每个元素都在 [minValue, maxValue] 内
且子数组总和 <= limit
```

### 两个条件必须分开判断

元素值范围不等同于总和阈值。

例如：

```js
memory = [3];
valueRange = [0, 2];
limit = 10;
```

虽然总和 `3 <= 10`，但 `3` 不在 `[0, 2]` 中，所以 `[3]` 仍然不合法。

一个越界元素不能出现在任何候选子数组中，因此它会切断数组：

```text
[2, 3, 1, 0, 2]
    ^ 越界

可独立处理 [2] 和 [1, 0, 2]
```

遇到越界元素时，窗口状态需要重置：

```text
left 移到该元素下一位
windowSum 归零
```

不是普通的“减掉一个左端元素”就足够，因为窗口不能跨过这个越界元素。

### 为什么可以用滑动窗口

本题保证 `memory` 的元素非负。

```text
右边加入新元素：窗口和只会增加或不变
左边移除元素：窗口和只会减少或不变
```

所以窗口和大于 `limit` 时，持续移动 `left` 一定能让窗口和恢复合法；这就是本题可以用标准可变滑动窗口的原因。

### 手推：窗口从超限恢复合法

```js
memory = [2, 0, 1, 0, 2];
limit = 2;
```

走到下标 `2`、加入元素 `1`：

```text
窗口 [2, 0, 1]
windowSum = 3，超过 limit = 2
```

移除左端 `2`：

```text
windowSum = 3 - 2 = 1
left：0 -> 1
窗口变为 [0, 1]，恢复合法
```

### 为什么答案累加 `right - left + 1`

若当前合法窗口是 `[left, right]`，以 `right` 为结尾、合法的子数组是当前窗口及其所有后缀：

```text
left = 1, right = 3
窗口 [0, 1, 0]

[0, 1, 0]  // 下标 [1, 3]
[1, 0]     // 下标 [2, 3]
[0]        // 下标 [3, 3]
```

共有：

```text
right - left + 1
= 3 - 1 + 1
= 3
```

个。

这些后缀都合法，因为移除左端的非负元素不会让总和变大，并且当前窗口中不存在值越界元素。

### 待实现的执行顺序

```text
右边界读取当前值
-> 若值越界：重置窗口，继续下一轮
-> 否则加入 windowSum
-> 当 windowSum > limit：while 移除左端并 left++
-> 窗口合法后：result += right - left + 1
```

### 复杂度与边界

- 时间复杂度：`O(n)`，左右指针各只向右移动。
- 额外空间：`O(1)`。
- 必测边界：元素等于范围边界、元素值越界、`limit = 0`、连续多个越界值、单元素刚好等于 `limit`。
